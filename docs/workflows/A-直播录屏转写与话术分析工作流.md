# A 部分：直播录屏、转文字与话术分析工作流

## 1. 目标

把一场直播从“录屏文件”加工成可复用的业务资料：

`录屏 -> 音频 -> 本地转写 -> 时间轴 -> 单场分析 -> 话术表 -> 多场归纳`

重点不是逐字保存主播说过什么，而是识别：

- 每个时间段在讲什么；
- 主播如何建立信任和权威；
- 什么时候要求关注、点赞、灯牌、进群、提交案例或下单；
- 内容主线如何推进到转化动作；
- 哪些话术可以迁移到我们的直播间。

## 2. 输入与输出

### 输入

- OBS 录制的 MP4 文件；
- 主播名称、录制日期、直播间主题；
- 可选：直播间画面、商品链接、粉丝群信息和实际转化数据。

### 输出

每场录音建议生成以下目录：

```text
output/recordings/<recording-id>/
  audio/normalized.wav
  metadata/media.json
  transcript/transcript.json
  transcript/transcript.txt
  transcript/transcript.srt
  analysis/transcript-index.md
  analysis/outline-10min.md
  analysis/analysis-report.md
```

最终沉淀：

- 单场直播分析报告；
- 分钟级直播动作时间线；
- 可复用话术表；
- 主播类型和转化路径对比表；
- 进入 B 部分时可使用的私信承接场景。

## 3. 标准流程

### A1. 录屏

使用 OBS 录制抖音直播间，确认同时录入：

- 直播画面；
- 电脑声音；
- 麦克风声音，如有需要；
- OBS 的录制时间和文件名。

录制完成后不要直接覆盖原始文件。原始视频作为证据文件保存，后续只处理复制或派生文件。

### A2. 提取音频

从 MP4 中提取单声道或双声道 WAV，统一采样率，便于本地模型处理。当前项目使用 FFmpeg 和 `extract_audio.ps1`。

质量检查：

- 音频时长与视频基本一致；
- 能听到主播主体声音；
- 没有明显静音、爆音或错录其他程序声音；
- 记录音频文件大小和时长。

### A3. 本地语音转文字

当前采用 FunASR + SenseVoiceSmall，本地运行，不需要 OpenAI API Key。

输出三种格式：

- JSON：保留时间戳和分段，供程序分析；
- TXT：便于人工阅读；
- SRT：便于回看视频和定位原句。

转写完成后先做质量抽查，不要直接把 ASR 结果当作事实。重点核对：人名、商品名、价格、平台词、数字、成语和口头禅。

### A4. 建立时间索引

按 1 分钟或 5 分钟生成索引，再按 10 分钟形成阶段大纲。时间索引至少保留：

```text
开始时间
结束时间
原文片段
主题标签
互动/转化标签
```

建议标签：

`痛点`、`建立信任`、`专业解释`、`故事背书`、`公屏互动`、`关注`、`点赞`、`灯牌`、`粉丝群`、`作业`、`私信`、`商品`、`链接`、`稀缺`、`售后`、`收尾`

### A5. 单场分析

每场报告固定回答四个问题：

1. 这场直播的核心主线是什么？
2. 主播每个阶段在完成什么任务？
3. 观众被要求做了哪些动作？
4. 哪些动作是轻转化、中转化和深转化？

单场报告建议使用以下结构：

```text
核心主线
按时间阶段拆解
主要转化动作
信任建立方式
用户承接方式
可复用话术结构
风险和待核对信息
```

### A6. 提炼话术表

不要照抄整场直播，要把原始表达抽象为模板：

| 场景 | 目的 | 话术结构 | 触发条件 | 下一步动作 |
|---|---|---|---|---|
| 开场 | 留住用户 | 痛点 + 结果承诺 | 新用户进入 | 关注/停留 |
| 解释问题 | 建立专业感 | 现象 + 原因 + 判断 | 用户产生共鸣 | 扣关键词 |
| 互动 | 筛选用户 | 提问 + 数字选项 | 主题讲完一段 | 公屏回答 |
| 个案承接 | 进入私信 | 共性内容无法覆盖个体情况 | 用户主动求助 | 合规私信沟通 |
| 收尾 | 形成复访 | 总结 + 下次内容预告 | 直播结束 | 关注/下次进入 |
```

### A7. 多场统一分析

把不同主播放入同一套维度比较：

- 内容定位；
- 目标用户；
- 信任来源；
- 互动方式；
- 转化起点；
- 转化升级点；
- 最终承接点；
- 收尾和复访方式。

## 4. A 部分的验收标准

- 每个有效录音都有完整音频和转写文件；
- 能按时间定位关键话术；
- 报告能区分内容、互动和转化；
- 不把 ASR 错字、价格或商品名未经核对地写成结论；
- 话术表是可改写的结构模板，而不是原文堆积；
- 能明确指出下一步应该进入 B 还是直接结束用户路径。

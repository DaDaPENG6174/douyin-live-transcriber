# C 部分：添加外部联系方式后的用户承接工作流

## 1. 目标

当用户已经通过合规流程进入微信或其他获准的外部联系渠道后，完成：

`确认身份与来源 -> 建立信任 -> 明确问题 -> 匹配话术/服务 -> 跟进结果 -> 沉淀案例`

本文件先搭建骨架。具体的微信现成话术表到位后，再把它们填入对应节点，形成可执行版本。

## 2. 用户进入后的第一步

在首次沟通中确认：

- 对方是谁、来自哪一场直播；
- 对方是主动咨询还是被邀请；
- 对方现在最想解决的一个问题；
- 对方期待的是建议、方案、服务还是资料；
- 是否同意继续沟通和接收相关信息。

不要一上来连续发送大量长文、语音或销售内容。先让用户把问题说完整。

## 3. 标准服务流程

### C1. 欢迎与来源确认

记录：

```text
用户昵称：
平台昵称：
来源主播：
来源录音/直播时间：
进入渠道：
首次联系时间：
```

### C2. 问题收集

使用开放问题了解背景：

- 现在发生了什么？
- 这件事持续多久了？
- 你已经尝试过什么？
- 你最希望得到什么结果？
- 哪些信息你不希望被记录或转发？

每次只推进一个核心问题，避免把用户带入无关话题。

### C3. 用户分层

可以先建立简单标签：

- 内容咨询；
- 情感/关系个案；
- 商品咨询；
- 服务意向；
- 已成交待跟进；
- 售后或投诉；
- 暂无明确需求。

标签只用于服务，不用于夸大承诺、骚扰或未经同意的营销。

### C4. 选择对应话术

根据用户类型，从后续提供的话术表中选择：

| 用户类型 | 需要匹配的内容 |
|---|---|
| 内容咨询 | 直播重点、资料、公开方法 |
| 个案咨询 | 信息收集、边界说明、分析步骤 |
| 商品咨询 | 产品信息、适用范围、价格、售后 |
| 服务意向 | 服务内容、交付方式、费用、时间 |
| 已成交 | 使用说明、交付确认、复购/售后 |
| 售后投诉 | 事实核对、处理时限、升级负责人 |

### C5. 给出下一步

每次沟通结束都要有明确动作，例如：

- 用户补充三项背景信息；
- 主播/顾问在某个时间前回复分析；
- 用户查看一份资料后反馈；
- 用户确认是否购买或预约；
- 售后进入工单处理。

不要只说“有问题再找我”，这会让线索无法推进，也无法判断用户是否真正解决。

### C6. 跟进与结案

记录：

- 用户是否回复；
- 是否完成约定动作；
- 用户是否满意；
- 是否产生下一步需求；
- 是否需要停止联系；
- 结案原因。

## 4. 微信话术表的建议结构

等用户提供现成话术后，建议整理成以下字段：

| 编号 | 使用场景 | 用户状态 | 目标 | 发送话术 | 禁用表达 | 下一步 |
|---|---|---|---|---|---|---|
| C-01 | 首次添加 | 新进入 | 确认来源 | 待填 | 待填 | 询问核心问题 |
| C-02 | 用户倾诉 | 情绪较强 | 稳定情绪 | 待填 | 待填 | 收集背景 |
| C-03 | 需要个案 | 信息不足 | 补充材料 | 待填 | 待填 | 约定回复时间 |
| C-04 | 商品咨询 | 有购买意向 | 说明产品 | 待填 | 待填 | 确认需求 |
| C-05 | 犹豫 | 未决策 | 处理顾虑 | 待填 | 待填 | 用户自主决定 |
| C-06 | 售后 | 已成交 | 解决问题 | 待填 | 待填 | 工单/结案 |

## 5. C 部分的边界

- 不承诺无法控制的结果；
- 不冒充医生、律师、心理治疗师或其他专业身份；
- 涉及自伤、家暴、诈骗、医疗或法律问题时，优先建议用户寻求专业机构帮助；
- 不擅自转发用户聊天记录、照片或隐私信息；
- 不用持续轰炸、制造焦虑或虚构名额促成成交；
- 对用户明确拒绝、拉黑或停止沟通的请求立即停止。

## 6. C 部分验收标准

- 新用户能在首次沟通中明确身份、来源和诉求；
- 每个用户都有状态和下一步；
- 话术按场景可检索，而不是一张长文；
- 能区分内容帮助、个案服务、商品咨询和售后；
- 重要承诺、费用、交付时间和售后方式都有记录；
- 用户拒绝后不会继续骚扰。
